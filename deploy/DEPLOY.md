# Развёртывание на Linux VPS

Потребуются Docker с Compose и HTTPS-прокси. Для запуска на локальной машине достаточно [быстрого старта](../README.md#быстрый-старт-docker-compose).

## Запуск

Из каталога репозитория на сервере:

```sh
docker volume create personal-kanban-prod-data
bash deploy/deploy.sh "$PWD" HEAD
cd /opt/personal-kanban
docker compose ps
curl -fsS http://127.0.0.1:18490/healthz
```

Скрипт ожидает права на каталог установки и доступ к Docker. Для другого каталога задайте `KANBAN_ROOT`. Для другого порта задайте `KANBAN_PORT` и укажите его в конфигурации прокси. Контейнер слушает только loopback хоста. Отдельный volume хранит SQLite и переживает обновления контейнера.

Добавьте [пример Caddyfile](Caddyfile.kanban) в конфигурацию Caddy, заменив `kanban.example.com` своим доменом. Укажите публичный DNS для этого сервера и разрешите входящие 80/443. Пример рассчитан на Caddy на том же хосте, который перезаписывает `X-Forwarded-For` адресом клиента. Порт 18490 оставьте закрытым снаружи.

После настройки HTTPS получите начальный токен владельца:

```sh
docker compose exec kanban cat /data/bootstrap-token.txt
```

Войдите на своём домене, сохраните токен в менеджере паролей и удалите файл из контейнера:

```sh
docker compose exec kanban rm /data/bootstrap-token.txt
```

MCP доступен по пути `/mcp` на том же HTTPS-адресе. [Агентские токены и подключение](../README.md#mcp).

## Обновление и копии

Скачайте нужный коммит и снова запустите `deploy/deploy.sh`, указав путь к репозиторию и ревизию. Скрипт собирает образ из коммита, делает SQLite-копию работающей БД, проверяет миграцию на копии и запускает новую версию. При провале проверки здоровья восстанавливает предыдущий образ и резервную копию, если они существуют.

Копии перед обновлением находятся в `backups/` внутри каталога установки. Для ручной копии или восстановления запустите `scripts/backup.sh` или `scripts/restore.sh` из каталога Compose. Храните копии приватно, поскольку в них есть задачи, агентские заметки и хэши токенов.
